PROJECT: TaskFlow — Multi-tenant project management SaaS (MVP)

1. PRODUCT OVERVIEW
TaskFlow helps software teams plan sprints, track tasks, and report delivery metrics. The MVP targets B2B customers (5–200 users per organization). Each customer is an "Organization" with isolated data. Users belong to one or more organizations via invitation.

2. ACTORS & ROLES
- Super Admin (platform operator): manage tenants, view usage, suspend accounts.
- Org Admin: invite users, configure org settings, billing contact.
- Project Manager: create projects, sprints, assign work, view burndown.
- Developer: update task status, log time, comment, link PRs.
- Viewer: read-only access to projects and reports.
RBAC must enforce role permissions at API and UI level. A user may hold different roles in different organizations.

3. AUTHENTICATION & SESSIONS
- Email/password registration with email verification (link expires in 24 hours).
- Login returns JWT access token (15 min) and refresh token (7 days, httpOnly cookie).
- Password policy: min 12 chars, at least one upper, lower, digit, symbol; block common passwords list.
- Forgot password: one-time reset link, single use, expires 1 hour.
- Optional SSO (Google Workspace) — Phase 2; document as out of scope for MVP but reserve extension points.
- Account lockout after 5 failed logins in 15 minutes; audit log entry required.
- MFA (TOTP) — Phase 2; note in assumptions.

4. CORE FUNCTIONAL REQUIREMENTS

4.1 Organizations & Users
- Org Admin creates organization profile (name, timezone, default sprint length).
- Invite user by email; invite pending 7 days; resend max 3 times.
- Accept invite creates membership with assigned role.
- Deactivate user: cannot login but historical assignments remain for audit.

4.2 Projects & Backlog
- PM creates Project (name, key prefix e.g. TF, description, visibility: private/org).
- Backlog items: Epic, Story, Task, Bug (hierarchy: Epic → Story → Task).
- Fields: title, description (markdown), priority (P0–P3), status, assignee, story points, labels, due date.
- Drag-and-drop reorder backlog; optimistic UI with server reconciliation.
- Duplicate detection warning if title similarity > 85% within same project (optional heuristic).

4.3 Sprints
- PM creates Sprint (name, start/end date, goal); max one active sprint per project.
- Move stories from backlog to sprint; capacity view by assignee (sum of story points).
- Close sprint: incomplete stories return to backlog unless explicitly carried over.

4.4 Comments & Activity
- Threaded comments on any work item; @mention notifies user (in-app + email).
- Activity feed: created, status change, assignment, comment (immutable audit trail).

4.5 Reporting (MVP)
- Burndown chart per active sprint (remaining points vs days).
- Velocity: last 3 closed sprints average completed points.
- Export CSV for sprint summary (org admin and PM only).

4.6 Notifications
- Email for: invite, mention, assignment, sprint start/end reminder.
- In-app notification center with read/unread; retain 90 days.

5. NON-FUNCTIONAL REQUIREMENTS
- Availability: 99.5% monthly for API (excluding planned maintenance).
- API p95 latency < 300ms for read, < 500ms for write under 100 concurrent users per org.
- Support 10,000 organizations, 500,000 users total (horizontal scaling design).
- RPO 1 hour, RTO 4 hours for production.
- GDPR: EU data residency option (Frankfurt region); right to erasure within 30 days of request.
- WCAG 2.1 AA for web UI (keyboard nav, contrast, screen reader labels).
- Audit logs retained 2 years; tamper-evident storage.

6. INTEGRATIONS (MVP scope)
- Webhook outbound on task status change (HMAC-signed payload, retry 3 times).
- GitHub: link commit/PR to task ID via #TF-123 in message (read-only display).
- Jira import (CSV) — one-time migration tool for backlog (Phase 1.5 if time).

7. API (REST, versioned /v1)
- JSON only; OpenAPI 3.1 published.
- Pagination: cursor-based, default page size 50, max 100.
- Idempotency-Key header for POST that create resources.
- Rate limit: 1000 requests/hour per API key per org.
- Standard errors: problem+json with code, message, correlation_id.

8. DATA & COMPLIANCE NOTES
- PII: email, name, IP at login; encrypt at rest (AES-256); TLS 1.2+ in transit.
- No storage of payment card data (Stripe Checkout only).
- SOC2-friendly logging: who did what, when, on which resource.
- Data export for org admin (JSON bundle) on request.

9. CONSTRAINTS & ASSUMPTIONS
- Web app: React + TypeScript; API: Python FastAPI; DB: PostgreSQL 16.
- Deploy on AWS (EKS); CI/CD GitHub Actions; feature flags via LaunchDarkly later.
- Mobile native apps out of scope for MVP.
- Assume Stripe for billing in Phase 2; MVP is free tier only with usage caps (5 projects, 20 users).

10. OPEN QUESTIONS (agents should flag if ambiguous)
- Should viewers see burndown for all projects or only assigned?
- Max attachment size for task descriptions (proposed 5 MB)?
- Single active sprint per project — confirm with product owner.

11. SUCCESS CRITERIA FOR MVP RELEASE
- Org can onboard, invite team, run 2-week sprint, close sprint, export report.
- Security review passes internal checklist; no critical findings open.
- Load test: 50 concurrent users per org without error rate > 1%.
